# 环境搭建记录（2026-11-11）

## 目标
在 Windows 宿主机上用 VMware 跑一台 Linux，能用 SSH 从宿主机远程登录，作为后续所有实验的基础环境。

## 环境清单

| 项 | 值 |
|---|---|
| 宿主机 | Windows 11 |
| 虚拟化 | VMware Workstation（`C:\Program Files (x86)\VMware\VMware Workstation`） |
| 虚拟机 | Rocky Linux 8.10（Green Obsidian），内核 4.18 |
| 网络模式 | 桥接（VM 获得 10.0.0.x 地址） |
| VM 资源 | 3.5G 内存 / 30G 磁盘 |
| SSH 客户端 | Windows OpenSSH（`ssh -V` → OpenSSH_for_Windows_9.5p1）+ FinalShell |

## 踩过的坑

### 坑 1：普通用户没有 sudo
- 现象：`rocky is not in the sudoers file. This incident will be reported.`
- 原因：RHEL 系默认只有 `wheel` 组成员能 `sudo`；`usermod` 也需要 root
- 解法：控制台以 root 执行 `usermod -aG wheel rocky`，**退出重登后**才生效
- 教训：Linux 权限靠「组 + 重新登录」，不是装完就有

### 坑 2：ICMP 不通但 SSH 通
- 现象：宿主机 `ping 10.0.0.150` 失败，但 22 端口可连
- 原因：桥接环境下 ICMP 常被防火墙丢弃
- 结论：判断服务是否可达，**以 TCP 端口为准**，别用 ping 下结论

### 坑 3：桥接 IP 会变
- 现象：DHCP 续租后 IP 变化，SSH 连不上
- 解法：路由器做 MAC 绑定，或改用 NAT + 端口转发
