# GitHub 2FA 配置记录（2026-11-12）

## 为什么配

1. 账号安全：只靠密码，一旦泄露就全丢
2. GitHub 对贡献者要求 2FA，早晚要用
3. 简历里放 GitHub 链接，账号可信度是加分项

## 过程与踩坑（真实记录）

### 环境限制
- 家里网络对 `github.com` 时通时断（hosts 切换 IP 兜底，见 [GitHub 访问排查](2026-11-11-GitHub访问排查.md)）
- 手机应用商店搜不到官方 `Microsoft Authenticator`，第三方"验证器会员"App 是收费仿制品 → **没用**
- 最终方案：**本地自己实现 TOTP**（RFC 6238），纯离线、不联网、不上传密钥

### 坑 1：验证码一直失败
排查顺序（对的顺序）：
1. **时钟偏差** → 本机与服务器时间一致，排除
2. **密钥长度/完整性** → 只复制了 16 位里的前 8 位，**密钥不全**
3. **字符混淆** → `O` vs `0`、`I` vs `1`（base32 里没有 0/1）
4. 最后才怀疑算法

### 坑 2：输入框里的灰字是"占位符"，不是已输入
- 现象：输入框显示 6 位数字，但「保存」按钮是灰的、点不动
- 原因：那是灰色占位文本；必须**点击输入框、手动键盘输入**，按钮才会激活
- 教训：粘贴不一定触发前端的事件监听，关键表单**手打**最稳

### 坑 3：重新配置 → 密钥会变
- 每次点「取消」重来、或刷新页面，GitHub 都会生成**新密钥**，旧密钥立即作废
- 所以顺序必须是：**拿密钥 → 立即算码 → 立刻提交**，别拖

### 坑 4：网页被封 ≠ 用不了
- `github.com` 打不开时，**SSH 通道（22 端口）仍然正常**，`git push` 不受影响
- 需要网页操作时，用**手机热点**即可（走不同出口）

## 结果

- [x] 认证器应用已启用（本地 TOTP 脚本，16 位密钥）
- [x] 恢复码 16 个：**下载 + 手机截图 + 纸质各一份**
- [x] 退出后重新登录（密码 + 6 位码）验证通过

## 技术笔记：TOTP 到底怎么算的

```
code = HOTP(K, T) 其中 T = floor(unix_time / 30)
HOTP(K, C) = Truncate(HMAC-SHA1(K, C))
```

1. 密钥是 **base32** 编码（A-Z + 2-7，没有 0/1/8/9）
2. 计数器 = 当前 Unix 时间 / 30 秒，按 8 字节大端打包
3. HMAC-SHA1 得到 20 字节摘要
4. 取最后一字节低 4 位作偏移，从该位置取 4 字节
5. 最高位清零，`% 1000000`，补零到 6 位

**同一时间窗内，任何客户端算出来都一样**——所以不需要买任何"验证器会员"。

## 安全提醒

- 密钥文件（`.totp_github.secret`）等于第二把钥匙：**不进网盘、不发微信**
- 恢复码和密码要分开存放
- 换电脑前，先把密钥文件带过去，或重新配置 2FA
