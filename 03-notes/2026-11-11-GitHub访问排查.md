# GitHub 访问排查记录（2026-11-11）

## 现象

浏览器打开 `https://github.com/login` → **`ERR_CONNECTION_RESET`（连接被重置）**。
但奇怪的是：同一台机器上 `github.com` 首页能开、`ssh -T git@github.com` 能通。

## 排查过程

| 步骤 | 命令 | 结果 |
|---|---|---|
| 1. 看解析 | `Resolve-DnsName github.com` | `20.205.243.166` |
| 2. 测端口 | `Test-NetConnection github.com -Port 443` | **False（不通）** |
| 3. 测其它 IP | `Test-NetConnection 140.82.112.3 -Port 443` | **True（通）** |
| 4. 测静态资源 | `185.199.108.215:443` | True |
| 5. 测 SSH | `ssh -T git@github.com` | 通（22 端口正常） |

**根因**：DNS 把 `github.com` 解析到一个**不通的 IP**（20.205.243.166），而 GitHub 在美国的其它 IP（140.82.112.x）是通的。

## 解决方案：改 hosts

用管理员权限编辑 `C:\Windows\System32\drivers\etc\hosts`，追加：

```
# ==== github access fix ====
140.82.112.3      github.com
140.82.112.6      api.github.com
140.82.113.9      codeload.github.com
185.199.108.215   github.githubassets.com
185.199.108.133   raw.githubusercontent.com
185.199.108.133   objects.githubusercontent.com
185.199.108.133   avatars.githubusercontent.com
# ==== end github fix ====
```

然后 `ipconfig /flushdns`，重新打开浏览器。

**效果**：`github.com` 解析变为 `140.82.112.3`，443 通，网页可访问。

## 遗留问题

- `/settings/*` 这类深层页面仍**间歇性超时**（实测 6 次全超时，但偶有一次 2.5 秒返回 200）→ 多刷新几次，或换手机热点完成一次性配置（如加 SSH key、建仓库）
- 改 hosts 后浏览器偶发样式不全 → 说明 `github.githubassets.com` 也要一并指向可用 IP

## 经验（以后遇到同类问题照这个查）

1. **别只 ping**：ICMP 不通不代表网络不通，**以 TCP 端口为准**（`Test-NetConnection IP -Port 443`）
2. **区分层次**：DNS 解析 → TCP 连通 → TLS 握手 → HTTP 响应，逐层排除
3. **多 IP 对比**：同一域名解析出多个 IP 时，逐个测，把通的写进 hosts
4. **SSH 和 HTTPS 是两条路**：网页打不开 ≠ `git push` 不能用
5. **临时方案要留后路**：改 hosts 前先备份（`hosts.bak`），写个回滚脚本
