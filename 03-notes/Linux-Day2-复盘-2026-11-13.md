## 二、三个坑（现象 → 原因 → 正确做法）

### 坑 1：`su` 之后 `~` 会骗你

- **现象**：`su root` 后提示符是 `[root@cys rocky]#`（当前目录还在 `/home/rocky`），但 `~/text0` 被解析成 `/root/text0`，于是 `cp` 报"无法创建目录"。
- **原因**：util-linux 的 `su` 不带 `-` 时**不改当前目录**，只把 `HOME`、`SHELL` 换成目标用户的 → `~` 变成 `/root`。
- **补充**：`su` 不带 `-` 时 PATH 也沿用旧环境（可能缺 /usr/sbin），所以规范写法是 `su -`。
- **正确**：完整切换用 `su -` 或 `sudo -i`；或干脆不进 root shell，一律写绝对路径：
  `sudo cp -a /etc /home/rocky/text0/`。
- **自检**：`pwd; whoami; echo $HOME` 三个值放一起看。

### 坑 2：`cp -r` 目标不存在时，内容会"铺"进去

- `cp -r /etc /root/text0`（`/root/text0` 不存在）→ 得到 `/root/text0/passwd`、`/root/text0/shadow`……**不是** `/root/text0/etc`。
- 目标**已存在且是目录** → 才得到 `目标/etc`。
- **正确**：cp 前先 `ls 目标父目录`，把路径写全。

### 坑 3：`du` 和 `find` 语法混用

- `du -sh /root/text0/etc -type f | wc -l` → `du: invalid option -- '/'`、`非法的 -t 参数`，`wc` 得到 0。
- **正确**：看大小 `du -sh 目录`；数文件 `find 目录 -type f | wc -l`。`wc -l` 数的是输出行数，不是文件数。

## 四、今天复习到的命令（#1–6）

| 命令 | 今天用它干了什么 | 要点 |
|------|-----------------|------|
| `pwd` / `ls` | 确认在 `~/text0`；`ls -l` 看副本属主与时间 | 删除前后都用 `ls` 确认 |
| `cd` | `cd ~`、`cd ~/text0` | `su` 后 `pwd` 与 `echo $HOME` 可能不一致 |
| `cp` | `cp -r /etc ~/text0`；`sudo cp -a` 思路 | 目标存在/不存在，行为不同；`-a` 保留权限/时间戳/软链 |
| `mv` | `sudo mv /root/text0 ~/text0/etc-full`（改名） | 目标不存在才是改名，别加末尾 `/` |
| `rm` | `rm ~/text0/text0`；`rm -f etc-full/hostname` | 先 `ls` 再 `rm`（计划备注） |
| 权限相关 | `sudo`、`chown -R` | /etc 敏感文件只有 root 能读 |
